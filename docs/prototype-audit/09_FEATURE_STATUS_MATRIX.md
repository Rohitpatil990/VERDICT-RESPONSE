## 1. Classification Taxonomy

Every capability in the VERDICT repository is categorized strictly into one of six mutually exclusive statuses:

| Status | Definition |
| :--- | :--- |
| **`IMPLEMENTED_AND_TESTED`** | Concrete source code exists, actively integrated into the build, and verified by passing automated unit/integration tests or harnesses. |
| **`IMPLEMENTED_NOT_VERIFIED`**| Source code exists and is integrated into runtime logic, but lacks dedicated automated unit test coverage. |
| **`PARTIAL`** | Substantial code exists but lacks complete lifecycle handling, full UI integration, or relies on simulated/mocked boundaries. |
| **`PROPOSED_ONLY`** | Concept appears in design documentation, earlier audits, READMEs, or architectural proposals, but no runnable production code exists. |
| **`NOT_IMPLEMENTED`** | Architecture/component is absent from repository code, builds, and dependencies. |
| **`BLOCKED`** | Feature cannot run or be tested due to an environmental, architectural, or hard dependency barrier. |
